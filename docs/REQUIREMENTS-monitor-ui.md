# 需求：把超越项显示出来 + 修正档位判定

日期：2026-10-20
前置：后端已产出 `usage_15s / usage_60s / run_queue / top_movers / top_services / stall_score / stall_level`，
**但前端一个都没展示**。没有 UI 的指标等于没做。

## 一、后端小修（1 处）

压测实测：8 核跑满时 `total=100`、`run_queue=14`，而 `stall_score=12.5`、档位「顺畅」。
分数本身没错（8 个自旋进程各占一核，确实没人被饿死），但**读者会困惑**。

加两条「档位下限」规则：

```text
若 run_queue > cores*1.5            → 档位至少「有压力」
若 usage_15s >= 95 且 run_queue>cores → 档位至少「有压力」
分数不变，只抬档位
```

理由：排队说明资源竞争已经发生，只是还没形成长时间等待。分数描述"等待"，档位描述"体感"。

## 二、前端（admin-web 系统页）

在现有系统信息卡片下方新增一块「负载与卡顿」，不改动已有卡片：

### 1. 顶部一行：卡顿指数

```text
┌────────────────────────────────────────────┐
│  卡顿指数 12.5  [顺畅]                      │
│  🟢 过去 60 秒有 5.7% 的时间在等 CPU          │
│  运行队列 4 / 8 核 · 15s 平均 14.3% · 60s 16% │
└────────────────────────────────────────────┘
```

- 数值 + 档位 Tag（顺畅=默认绿 / 有压力=橙 / 明显卡顿=红）
- 一行说明取 PSI cpu avg60，直接给百分比，别解释术语
- 右侧或下方显示 `run_queue / cores`、`usage_15s`、`usage_60s`

### 2. CPU 三档小图

一个横向三段条（1s / 15s / 60s），让"瞬时 vs 持续"一眼可辨；hover 显示具体值。

### 3. Top 服务（cgroup）

表格三列：单元名 / CPU% / 内存。取 `top_services`，最多 10 行，按 CPU 降序。

### 4. Top 归因（top_movers）

表标题用「最近 15 秒 CPU 增量」而不是「CPU 占用」，并标注「含已退出进程」。
列：进程名 / 增量 / 当前。已退出的行加灰 Tag「已退出」。

### 5. 无数据时

字段缺失（旧后端）时整块不渲染，不留空壳。
